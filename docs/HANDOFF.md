### 1.5 Мобильная адаптация
Основной файл: `src/app/page.tsx` (JSX-структура hero + мобильный `<style>` блок в конце файла).

- **Hero:** переведён на именованные `grid-template-areas` вместо вложенной левой колонки. На десктопе — прежняя 2-колоночная раскладка (визуализация справа, во всю высоту). На мобильном (`≤820px`) area-шаблон переопределяется в 1 колонку с порядком: бейдж → заголовок → **визуализация звонков** → абзацы → кнопка → строка доверия (картинка была в конце страницы, теперь между заголовком и первым абзацем, без дублирования DOM).
- **Кнопки:** второстепенная кнопка «Получить демо-доступ» удалена из hero и финального CTA-баннера полностью (не просто скрыта на мобильном) — по всему сайту убрана формулировка «Получить демо-доступ», везде «Запросить демонстрацию» (в финальном баннере — «...бесплатно»). Осталась только форма submit-кнопка с тем же текстом.
- **Шапка на мобильном (`≤560px`):** скрыты «Тарифы» и «Запросить демо» (как и «Возможности» — уже было скрыто раньше), остаётся только логотип.
- **Карточки «Как это работает» / «Что умеет»:** сначала попробовал центрирование (иконка+заголовок+текст по центру) — Юрий забраковал («криво», иконка оторвана от текста). Откатил на icon-left + текст-справа (как уже было в блоке «Что получает бизнес» — эталонный паттерн). Заодно унифицировал ширину карточек между всеми тремя секциями (`flex: "1 1 Npx", maxWidth: 340` вместо резинового CSS Grid `auto-fit minmax`) — раньше «Что умеет» тянулось на всю ширину контейнера на мобильном, а «Что получает бизнес» — нет, выглядело непоследовательно.
- **Таблица сравнения («Почему Call-Pilot»), два прохода:**
  1. Нашёл и исправил реальный CSS-баг, не связанный с сегодняшними правками (существовал раньше) — `.compare-head { display:none }` и `.compare-row { display:block }` имели ОДИНАКОВУЮ CSS-специфичность (оба — два class-селектора), и правило `display:block` для строк (идёт в коде ПОСЛЕ правила скрытия шапки) побеждало по правилу cascade «последнее правило при равной специфичности» — шапка таблицы («Параметр» / «Ручной контроль») протекала на мобильный вид, накладываясь на данные. Плюс blanket `background:transparent!important` на всех ячейках гасил фиолетовую подсветку строки «Call-Pilot», из-за чего пропадало визуальное различие «мы vs ручной контроль». Специфичность исправлена через комбинированный селектор `.compare-row.compare-head`, подсветка восстановлена через `[data-label="Call-Pilot"]`.
  2. Юрий увидел исправленную версию и всё равно назвал её «кашей» — баг был устранён, но плоский чередующийся список (5 категорий × 2 строки без чёткой группировки) сам по себе читался плохо. Второй проход — полный редизайн мобильной версии: каждая категория (Охват/Скорость/Объективность/Данные в CRM/Формат) теперь отдельная карточка с рамкой, скруглением и тенью, между карточками gap 14px (вместо единой рамки на всю таблицу с внутренними border-bottom), название категории — заголовок карточки с подчёркиванием снизу и увеличенным шрифтом, лейблы «РУЧНОЙ КОНТРОЛЬ»/«CALL-PILOT» уменьшены и приглушены (opacity, меньший размер), чтобы сами значения сравнения читались первыми.
- **Тарифные карточки:** имя тарифа и цена центрируются на мобильном (по просьбе Юрия), фич-лист остаётся слева-выровненным (чек-лист с иконками читается хуже по центру).
- **Карточки «Как это работает»/«Что умеет», второй проход:** первая версия (центрирование) не понравилась Юрию визуально — откатил на icon-left (см. выше), это и есть финальная версия.

**⚠️ Не проверено вживую на реальном мобильном устройстве.** Инструмент resize окна браузера в этой сессии не работал (окно не меняло реальный `window.innerWidth` несмотря на «успешный» ответ tool). Все мобильные правки сделаны на основе чтения кода/логики CSS и уже проверенных паттернов с других секций страницы, задеплоены, но **не подтверждены живым скриншотом на ≤560px**. Нужна проверка с реального телефона Юрия — если что-то выглядит не так, следующему агенту/сессии нужно будет использовать реальное устройство или рабочий resize-инструмент (в этой сессии `mcp__claude-in-chrome__resize_window` не менял фактический viewport несмотря на «Successfully resized»).
